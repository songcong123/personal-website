[上一篇](/blog/web-terminal-claude-code/)写了路线 C 的搭建教程。这篇是**施工日志**：一天里到底改了什么、为什么这么改、踩了哪些坑。如果你只想抄作业，看教程那篇就好；如果你想理解"把家用笔记本服务器化"的完整思路，这篇是给你 的。

## 改造前 vs 改造后

| | 昨天 | 今晚 |
|---|---|---|
| 手机能连吗 | ✅ SSH 已通 | ✅ + 浏览器直连（免装一切） |
| 公司能连吗 | ❌ | ✅ 只读口实时看进度，零数据回流 |
| 断线后任务 | `claude -c` 续对话（跑一半的丢了） | tmux 原画面续跑，一字不丢 |
| 电脑睡眠后 | Tailscale 卡死，要人肉重登 | 看门狗 5 分钟内自愈 |
| 重启后 | 一片空白 | 4 个服务全部自启 |

**一句话：从"一台要人伺候的笔记本"变成"一台自愈的迷你服务器"。**

## 改动一：保活三件套（服务器化的地基）

服务器的前提是**活着**。三件事：

1. **电源**：插电永不睡眠 + 合盖不动作（电源计划里把交流电的睡眠/休眠都设 0，合盖动作用 `LIDACTION 0`）。电池状态下保留 1 小时睡眠——防止塞包里过热
2. **服务自愈**：Tailscale 服务配崩溃自动重启（`sc failure` 三连），两个网页终端和隧道各注册 SYSTEM 计划任务开机自启
3. **看门狗**：计划任务每 5 分钟检查 `tailscale status`，离线就重启服务——专治睡眠唤醒后卡死

### 看门狗差点变成凶手

第一个版本的看门狗上线 20 分钟后，我把 Tailscale 服务杀掉了——不是崩的，是**看门狗自己干的**，每 5 分钟杀一次。凶手是 PowerShell 5.1 的编码陷阱：

> `tailscale status --json` 的输出里有中文（我的 Tailscale 显示名），PS 5.1 管道按 GBK 解码 UTF-8，JSON 必炸 → 看门狗永远误判"离线" → 到点就重启服务。

修复：先设 `[Console]::OutputEncoding=UTF8`，再加正则兜底，最后让看门狗**每次自检写一行日志**——没有日志的自动化等于盲飞，这次教训之后我把所有定时任务都配了落盘日志。

## 改动二：网页终端 + tmux（教程见上一篇）

架构和参数教程里都有，这里只记教程没写的**决策过程**：

- **为什么双端口而不是一个口加开关**：安全边界要靠架构而不是纪律。只读口是 ttyd 不加 `-W` 参数的纯摄像头，"不能输入"是物理属性，不依赖任何人手不滑
- **为什么两条公网隧道都要**：Funnel 域名固定但国内被墙，trycloudflare 国内直连但域名随重启变。互为备份，一个给公司（走代理、加书签），一个给自己（手机流量直开）
- **为什么升级 Git 而不是换 DLL**：新 tmux 配 2022 年的 msys 运行时会静默退出。手动替换 `msys-2.0.dll` 是能跑，但升级 Git 是**受支持的正规路径**——顺手把拖了三年的 Git 2.39 升到 2.55

### tmux 同屏的原理（一句话版）

tmux 是"演播室"：claude 在演播室里一直干活，画在一张内存画布上；浏览器、SSH、只读口都只是对着画布的摄像头。关电视节目不停，这就是断线不死；所有摄像头看同一块画布，这就是实时同步。

## 改动三：公司接入的行为准则

架构给公司开了"只能看的摄像头"，但读写口难免自己用。给自己立了张军规表：

- 🔴 **任何粘贴都是高危**：公司代码、报错日志、内网地址、token、git 地址+凭证——一个字节都不进终端。判断标准：*按下 Ctrl+V 前问自己，这段文字愿意直接发给外人吗？*
- 🟡 **留痕即风险**：别在 401 弹框点"保存密码"（公司浏览器配置 IT 可导出）、网址密码不进企业微信、离位 Win+L
- ✅ **标准姿势**：公司只读口看大屏，指挥用手机

## 排坑实录（本文最有含金量的部分）

十个坑，全是真实踩出来的，现象→真凶→解法：

| # | 现象 | 真凶 | 解法 |
|---|---|---|---|
| 1 | 看门狗每 5 分钟杀服务 | PS 5.1 用 GBK 解码含中文的 JSON | `[Console]::OutputEncoding=UTF8` + 正则兜底 |
| 2 | PS 脚本"运行成功"但什么都没干 | 字符串里写了 `&&`，PS 5.1 整文件解析失败且**无任何报错** | 换 `;` 分隔；重要脚本首行写日志证明自己活过 |
| 3 | 计划任务注册返回成功但查不到 | `-RepetitionDuration 3650天` 静默失败；另 SYSTEM 任务对非管理员查询本来就看不清 | 用 `schtasks /create`，验证要提权查 |
| 4 | `schtasks /query` 报"无效参数" | Git Bash 把 `/query` 转义成 `C:/Program Files/Git/query` | 包一层 `powershell.exe -Command` |
| 5 | Git 静默升级 exit 1，日志全无 | 安装器检测到运行中的 bash.exe（就是我自己的命令进程），静默模式下自动取消 | 安装器**脱离 shell 延迟 8 秒**启动；`/LOG=` 抓真凶 |
| 6 | tmux 装好运行 exit 127 无报错 | 新 tmux 配旧版 msys 运行时 | 升级 Git 到同年代版本 |
| 7 | 网页终端里 claude 弹"登录" | SYSTEM 的 `USERPROFILE` 指向系统目录，Node 不认 `HOME` 只认它 | 启动脚本显式 `set USERPROFILE=C:\Users\我` |
| 8 | tmux 报 missing terminal | Git Bash 的 terminfo 库没有 `tmux-256color` | `set -g default-terminal "screen-256color"` |
| 9 | claude 在终端里又弹信任界面 | tmux 会话出生在 `C:\Windows\System32`（SYSTEM 的老家） | 接入脚本第一行 `cd "$HOME"` |
| 10 | 改了 tmux 配置不生效 | 配置只在 tmux **服务进程**启动时读一次，旧进程还活着 | `taskkill /IM tmux.exe /F`（SYSTEM 进程要提权）再重连 |

坑 2 和坑 5 最值得记住：**静默失败比报错可怕十倍**——前者让你以为成功了，排查方向全错。

## 最终形态

```
           ┌─ 手机 SSH（Tailscale，最稳）
三端接入 ──┼─ 浏览器·读写口（双隧道，免装直连）
           ├─ 浏览器·只读口（公司专用，零回流）
           └─ ToDesk（图形兜底）
                    ↓
        tmux 会话（断线不死，多端同屏）
                    ↓
        Git Bash → Claude Code（GLM 接入点）
                    ↓
        底座：永不睡眠 + 看门狗 + 全服务自启 + 充电上限 80%
```

一年前"远程用家里的电脑"还是个愿望，今天它成了三个网址。**普通笔记本和迷你服务器之间，隔的只是十几个认真对待的坑。**
